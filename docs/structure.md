# 文档体系

## 结构

软件手册是一部完整的书，建议采用下面的结构。

- **简介**：[必备] [文件] 提供对产品和文档本身的总体的、扼要的说明
- **快速上手**：[可选] [文件] 如何最快速地使用产品
- **入门篇**：[必备] [目录] 又称“使用篇”，提供初级的使用教程
  - **环境准备**：[必备] [文件] 软件使用需要满足的前置条件
  - **安装**：[可选] [文件] 软件的安装方法
  - **设置**：[必备] [文件] 软件的设置
- **进阶篇**：[可选] [目录] 又称“开发篇”，提供中高级的开发教程
- **API**：[可选] [目录|文件] 软件 API 的逐一介绍
- **FAQ**：[可选] [文件] 常见问题解答
- **附录**：[可选] [目录] 不属于教程本身、但对阅读教程有帮助的内容
  - **名词解释**：[可选] [文件] 名词解释
  - **最佳实践**：[可选] [文件] 最佳实践
  - **故障处理**：[可选] [文件] 故障处理
  - **版本说明**：[可选] [文件] 版本说明
  - **反馈方式**：[可选] [文件] 反馈方式

## 文件名

文档的文件名不得含有空格。

文件名中的英文必须使用半角字符，不得使用全角字符。文件名应与内容保持一致，因此文件名应为中文。

```
错误：glossary.md

正确：名词解释.md
```

为了醒目和行业规范，某些说明文件的文件名，可以使用纯英文大写字母，比如`README`、`LICENSE`。

文件名包含多个单词时，使用单词首字母大写

```
不佳：advanced usage.md

正确：Advanced Usage.md
```
